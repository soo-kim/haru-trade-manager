# Functional Spec (v0.1)

## 1. 목표와 범위

본 문서는 `docs/prd.md`의 기능 요구사항을 구현/테스트 가능한 단위로 정리한다.

### 포함 범위

- 한국 주식(코스피/코스닥) 자동 시그널 생성 및 주문 실행
- 루프 A/B/C, ConfigManager, 리스크 관리, 텔레그램, 대시보드, 백테스트
- 페이퍼/실계좌 모드 분리

### 제외 범위 (초기 릴리스)

- 웹소켓 기반 실시간 시세 처리
- 멀티 사용자 계정
- 해외주식/선물/옵션 지원

## 2. 도메인 엔티티

- `Symbol`: 종목 마스터/상태(전체 유니버스, 활성 유니버스, 블록리스트 여부)
- `Candle`: 타임프레임별 OHLCV
- `StrategyInstance`: 전략 타입 + 타임프레임 + 활성 시간대 + 파라미터
- `Signal`: 전략이 생성한 진입/청산 후보 이벤트
- `Order`: 주문 요청/상태/재시도 기록
- `Position`: 전략별 독립 포지션 상태(`OPEN`, `HALF_CLOSED`, `CLOSED`)
- `Config`: 시스템 설정 키/값
- `ConfigHistory`: 설정 변경 이력
- `AccountSnapshot`: 시점별 계좌 스냅샷
- `CashFlow`: 입출금 이벤트

## 3. 기능 요구사항 + 수용 기준

### FR-01 ConfigManager 중앙 관리

요구사항:
- 모든 설정 읽기/쓰기는 ConfigManager를 통해서만 수행
- 검증 실패 시 반영 금지
- 성공 시 메모리 + DB + 이력 동시 반영

수용 기준:
- 범위 밖 값 입력 시 4xx 성격 오류 반환
- 변경 성공 시 `config_history`에 1건 기록
- 재시작 후 마지막 값 복원

### FR-02 REST 요청 단일 관문

요구사항:
- 모든 외부 API 호출은 `RateLimitedClient`를 통해 순차 처리
- 최소 0.2초 간격 보장
- 주문 요청 우선순위가 데이터 요청보다 높음

수용 기준:
- 동시 호출 테스트에서 실제 전송 순서가 우선순위 정책과 일치
- 토큰 만료 5분 전 갱신 시도
- 토큰 갱신 3회 실패 시 시스템 정지 이벤트 생성

### FR-03 캔들 수집 및 증분 업데이트

요구사항:
- 초기 히스토리 배치 + 이후 증분 업데이트
- 마지막 진행 중 봉은 UPDATE, 신규 봉은 INSERT

수용 기준:
- 동일 기준시각 봉 중복 INSERT 없음
- 장중 진행 봉 값 변동 시 마지막 봉 1건만 UPDATE
- 타임프레임별 최소 수집 기간 충족 여부를 조회 가능

### FR-04 루프 B 시그널 생성

요구사항:
- 봉 마감 시점에만 전략 실행
- 서버 시간 offset 기반으로 마감 판단
- 생성 시그널은 큐에 적재하고 루프 A가 소비

수용 기준:
- 5분/15분/60분/일봉 마감 이벤트가 규칙대로 트리거
- 활성 시간대 밖 전략은 스킵 로그 기록
- 시그널 생성과 주문 실행 시점이 분리되어 저장됨

### FR-05 주문/포지션 상태머신

요구사항:
- 진입 지정가, 익절/손절/트레일링/강제청산 시장가
- 상태 전이: `OPEN` -> `HALF_CLOSED` -> `CLOSED`
- 미체결 지정가 자동 취소

수용 기준:
- `order_cancel_minutes` 경과 시 취소 요청 발생
- 1단계 익절 후 잔여 수량에 트레일링 적용
- 재시작 후 포지션 상태/트레일링 고점 복원

### FR-06 리스크 엔진

요구사항:
- ATR 기반 포지션 사이징
- 일손실/연속손절/동시포지션 한도 체크
- NXT 미수 진입 금지

수용 기준:
- 한도 초과 시 주문 대신 차단 로그 생성
- 미수 모드에서도 손실 기준은 자기자금 기준으로 계산
- 정지 조건 충족 시 정지 이벤트 + 텔레그램 발송

### FR-07 15:20 미수 강제청산

요구사항:
- 계좌 총 포지션 평가금액이 `daily_base_capital` 초과 시에만 실행
- `margin_close_priority` 순서대로 순차 청산하며 매 단계 재계산

수용 기준:
- 임계치 이하가 되면 즉시 중단
- 임계치 초과가 지속되면 우선순위 끝까지 진행
- 실행 내역(청산 순번/사유/전후 금액) 저장

### FR-08 텔레그램 인터페이스

요구사항:
- 알림: 진입/청산/리스크/정지/요약/설정변경
- 명령: 상태조회/설정변경/중단/재개/청산/리포트/블록리스트

수용 기준:
- 리스크 핵심 설정 변경 시 확인 단계(`/confirm`) 필요
- `/pause entry`는 진입만 중단, 청산 모니터링 유지
- `/pause all`은 자동 청산 포함 전체 자동동작 중단

### FR-09 성과 측정(TWR)

요구사항:
- 입출금 영향 제거를 위해 TWR 계산
- 스냅샷 기반 입출금 자동 감지 + 수동 보정 허용

수용 기준:
- 입출금 이벤트를 경계로 구간 수익률 분리 계산
- TWR, 누적손익, 실계좌 오차 지표 조회 가능

### FR-10 페이퍼 트레이딩 모드

요구사항:
- `TRADING_MODE=paper|live` 분기
- paper는 가상 주문/가상 포트폴리오 테이블 사용

수용 기준:
- 전략/리스크/시그널 코드는 모드와 무관하게 동일 동작
- 모드 전환은 환경변수 + 재시작으로 반영
- 합격 기준 리포트(`/paper_report`) 생성

## 4. 비기능 요구사항

- 신뢰성: 주문 상태 불명확 시 즉시 주문조회 후 1회만 재시도
- 복구성: 재시작 시 포지션/설정/토큰 복원
- 가시성: 구조화 로그(JSON), 치명 오류 알림
- 성능: 루프 B 정각 몰림 시에도 주문 요청 선처리 보장

## 5. 테스트 전략 (최소 세트)

- 단위 테스트
- ConfigManager 검증/이력
- 사이징 계산식/경계값
- 상태머신 전이

- 통합 테스트
- 루프 A/B/C + 큐 연동
- 주문 실패 후 조회/재시도 분기
- 15:20 강제청산 우선순위 동작

- 시뮬레이션 테스트
- 백테스트 N봉 신호 -> N+1 시가 체결 강제
- 페이퍼 모드 2주 샘플 재현

## 6. 추적 매트릭스 (PRD 연계)

- PRD 5장(루프/클라이언트) -> FR-02, FR-03, FR-04
- PRD 4장(진입/청산) -> FR-05
- PRD 6~7장(설정/리스크) -> FR-01, FR-06, FR-07
- PRD 8장(텔레그램) -> FR-08
- PRD 5.2/성과 -> FR-09
- PRD 12장(페이퍼) -> FR-10
